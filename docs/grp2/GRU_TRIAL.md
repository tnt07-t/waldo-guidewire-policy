# ViT experiment reference

## Implemented comparison protocol

Use [PROGRESS](PROGRESS.md) for run outcomes and provenance, [GRU_DEBUG_HANDOFF](GRU_DEBUG_HANDOFF.md) for current operation, and [Tran’s presentation source](../../tran/MIDPOINT.md) for figures and exact aggregate metrics. The design discussions below are historical rationale, not an instruction to launch their alternatives.

All development comparisons use episode-separated split position 0, seed 0, 267 training / 80 validation cases and 69 reserved test cases. Labels are operator-action proxies. DINOv2 Small/14 produces 384-value summaries after full-view proportional resize/padding to 518×518. Scale depth/time using training data only. Frozen runs use fresh heads, batch 32, Adam at .001 without decay except the explicit AdamW/.01 comparison, unweighted cross entropy and validation-BA checkpoint selection with patience 20. BA weights both recalls equally; selecting by BA does not rebalance training gradients.

| Step | Implemented change | Trainable parameters |
|---|---|---:|
| Late-goal GRU | Six image384 + depth/time2 steps → GRU64; final state + goal384 → 448→64→2 | 115,650 |
| AdamW GRU | Identical architecture; optimizer/decay change only | 115,650 |
| Early-goal GRU | Repeat goal384 at each step (770 inputs); retain late fusion | 189,378 |
| Summary-static | Latest384 + goal384 + all 12 depth/time values → 780→64→2 | 50,114 |
| Spatial grid | Frozen 37×37 patches pooled to 4×4; shared 384→16/ReLU projection; flattened grids + metadata → 524→64→2 | 39,890 |
| Last-block adaptation | Train entire final ViT block and summary-static classifier; earlier layers and separate output norm frozen | Recorded by trainer; do not infer from head count |

Classifier hidden layers use ReLU. Grid features preserve coarse spatial order but do not explicitly localize or match the wire and target. Summary-static and grid omit earlier visual frames, not numerical history. Comparisons change capacity as well as inputs; they are not perfectly isolated causal ablations.

## Last-block training and checkpoint contract

Implemented at `5d6407c`, with the later local cap/test change setting training/evaluation and overall limits to 1200 seconds each. Earlier 120/600-second limits describe the first attempt only. The overall deadline includes loading and final verification and may preempt training. An initial 60/65-minute proposal was superseded before execution.

Train attention, both MLP layers, internal norms/scales of the final block, plus both classifier layers. Use a shared pretrained encoder for latest and goal, fresh seed-0 classifier, block/head learning rates 1e-5/1e-3, Adam, zero decay and unweighted CE. These inherited settings make the initial comparison interpretable; they are not proven optimal. Effective batch 32 with physical microbatch 1 uses case-weighted accumulation, including the final 11-case batch. Recompute visual features; detached final embeddings cannot train their producing block. Ceilings are 100 epochs/900 updates/patience 20, not achieved work.

Retain only `best.pt`: adapted block/head, pretrained/frozen content identities, exact trainable scope, training-only scales and provenance. Reload reconstructs the base and checks predictions; a checkpoint’s presence alone does not verify it. The 20 MiB checkpoint storage cap includes temporary replacement copies. No automatic resume or retry. Keep logits, row/episode context and all private artifacts on Perlmutter.

The original 102-test synthetic suite passed locally and on Perlmutter (user-reported); actual pretrained readiness also passed. First real attempt hit the training cap after nine updates and zero scored epochs; the parent reported `worker_failed`, masking the budget-limited outcome. The second attempt saved eight epochs before the overall cap. Missing final reload/frozen checks remain unverified. See the milestone record for exact results.

## Adaptation rationale and unresolved questions

All five earlier comparisons froze the same encoder. Similar held-out scores across temporal, goal-fusion and grid changes motivated testing that shared assumption. Summary-static was retained because it was simple and competitive, not a statistically proven winner. A lower block learning rate and frozen prefix constrain updates but do not prevent memorization on 267 related examples. Last-block training cannot recover information absent from earlier tokens and may learn shortcuts rather than wire–route reasoning.

One-frame masking showed weaker tip sensitivity than background controls; it does not prove absent wire information. Prepared visibility, finite features and successful plumbing likewise do not establish useful representations. Small sample size, episode variation, overfitting, label ambiguity and class imbalance remain alternatives. A single case or isolated peak on repeatedly reused validation data is weak evidence.

If adapting improves training without validation, do not automatically unfreeze more blocks. The saved adaptation run instead has weak training BA near 53% and strong ADVANCE preference: inspect optimization, class contribution and checkpoint validity before extending. Training counts are 97 RETRACT/170 ADVANCE; unweighted loss gives the more common class more total influence. Training-derived weighting changes that objective, not necessarily feature quality. Do not combine weighting, thresholds, new representations and adaptation in one purportedly controlled test.

Alternatives retained for discussion: stronger regularization of a small frozen head; a lower-capacity adapter; matched goal+metadata versus latest+goal+metadata controls; explicit goal/current interaction; repeat seeds and full per-decision latency. None is established as superior or authorized as an automatic sweep. Spatial grids can dilute thin-wire changes and fixed coordinates need not align anatomy. Visual representation, temporal inputs and trainability are independent choices.

## Post-run proposals: regularization and goal use — 2026-11-03

**Evidence and scope:** the first full run is complete; [recorded curves/results](PROGRESS.md) show strong overfitting, not evidence that the goal was omitted. The implemented classifier receives the final 64-value GRU state concatenated with the 384-value goal encoding. The goal is encoded once and reused; it does not condition the GRU's history processing. Goal dependence and useful temporal reasoning remain unproven. The AdamW setup below was subsequently implemented locally at Tran’s “ok next” instruction. Other methods remain proposals; the AdamW code is committed and pushed (Tran-confirmed), and a follow-up real run completed; [the supplied result and provenance limits](PROGRESS.md) are recorded in progress. The allocation is released.

**Completed follow-up — AdamW weight decay:** replace Adam/no decay with AdamW at learning rate 0.001 and explicit weight decay 0.01; retain the frozen encoder, 64-unit GRU, classifier without dropout, split 0, seed 0, batch 32, fresh initialization, checkpoint rule, patience and existing work/time/storage limits. Apply decay to the trainable head parameters; the frozen encoder stays outside the optimizer. This is a training-recipe comparison, not proof of an isolated causal effect. The coefficient is a starting hypothesis, not an established optimum. The runner/tests are locally verified and committed at `481e517` on the debug branch; publication is complete (Tran-confirmed). The subsequent follow-up run completed with lower validation balanced accuracy and higher ADVANCE recall; saved revision/settings and best/final epoch metrics are now confirmed, with dirty-state details unverified; the curves were subsequently reviewed as recorded below. The best-to-final scores remain consistent with overfitting. See the progress milestone before any further experiment.

Weight decay gently shrinks weights each update while the learning update can still increase them. AdamW separates decay from Adam's adaptive gradient update; it is not equivalent to adding an L2 penalty to Adam's loss. Its shrinkage factor is `1 - learning_rate * weight_decay`: these proposed values give 0.99999 per update, not 1% shrinkage. An unchanged result may mean insufficient decay or another limitation; it does not establish that all weight decay fails. Recent research supports continued investigation, not this GRU's exact settings: [NeurIPS 2024](https://proceedings.neurips.cc/paper_files/paper/2024/hash/29496c942ed6e08ecc469f4521ebfff0-Abstract-Conference.html), [ICML 2025](https://proceedings.mlr.press/v267/wang25b.html).

**Why this first:** the baseline has zero decay and a clear training/validation gap. AdamW tests a low-cost change affecting the GRU and classifier without changing their inputs, parameter count or image preparation. Choosing it is a practical hypothesis, not evidence it beats the alternatives. The earlier classifier-dropout-first suggestion is superseded; dropout remains a later option.

| Alternative | Why defer or retain unchanged for this comparison |
|---|---|
| Early stopping | Already present: patience 20 on balanced accuracy. Validation loss and balanced accuracy can disagree; changing selection to loss would be a separate experiment. |
| Smaller architecture | Strong next candidate (hidden size 32 or feature projection), but changes representational capacity as well as regularization. |
| Data augmentation | Requires label-preserving transforms that keep goal/history geometry consistent and additional frozen-image encoding; cannot perform pixel augmentation on cached vectors. |
| Batch normalization | No demonstrated normalization fault; adds batch-dependent behavior rather than directly testing weight decay. |
| L1 | Encourages sparsity; no current evidence that sparse weights are the needed constraint. |
| Classifier dropout | Still reasonable, but addresses classifier activations; decay offers a first change across both trainable components without adding a layer. |

**Review after one bounded run:** compare against the existing baseline using the same selection rule; record actual epochs/updates, losses, balanced accuracy, both class recalls/confusion counts and freeze/reload checks. A smaller gap caused solely by worse training is not success. Inspect whether any validation gain is sustained rather than an isolated peak; one seed cannot establish robustness. Keep test reserved, release the allocation, and review before any further experiment. Matched static comparison and goal-use checks remain separate priorities; decay does not establish correct goal reasoning.

**Goal diagnosis and later architecture:** compare saved-checkpoint validation probabilities with correct versus shuffled goal features as a sensitivity check; unrealistic pairings limit interpretation, and sensitivity does not prove correct reasoning. A separately trained no-goal control and the matched latest-image + goal + full-metadata baseline address predictive benefit. If justified, compare a shared learned image projection 384→64 with late fusion against the same projection with the goal repeated at each GRU step: `[history64, goal64, depth, time]`, then classify final state plus projected goal. This separates compression from earlier goal access. Whole-image summaries may omit useful target/tip detail; spatial patch features or verified, normalized `goal_xy` are later representation experiments, not confirmed fixes. Operator-action proxy labels do not guarantee optimal goal-directed supervision; never invent action labels for shuffled goals.

## Conclusions after the first AdamW comparison — 2026-11-03

The bounded implementation works: both real development runs completed, freeze/reload checks passed and allocations are released. The AdamW comparison did not improve the agreed validation balanced-accuracy criterion (57.48% versus baseline 59.21%). Higher ordinary accuracy (61.25% versus 57.50%) came with a large class-recall tradeoff. At selected epoch 32, ADVANCE recall was higher and RETRACT recall lower; by final epoch 52, validation recalls were nearly equal and training RETRACT recall reached 94.85%. This does not establish an inherent AdamW preference for ADVANCE or inability to learn RETRACT.

Overfitting remains: between supplied epochs 32 and 52, training BA rose from 74.75% to 85.95%, while validation BA fell from 57.48% to 56.20% and validation loss rose. A smaller selected train/validation gap than the baseline is insufficient evidence of improvement because training performance also decreased. One seed, 80 validation cases, different selected epochs and an unexplained run dirty flag limit causal/robustness claims. Keep the baseline as the better observed BA reference; neither run establishes useful goal/history reasoning or final-test performance. [PROGRESS.md](PROGRESS.md) owns exact metrics and provenance.

## Curve review and goal-conditioned history proposal — 2026-11-03

**Observed curves:** Tran opened the AdamW learning-curves SVG on Perlmutter and supplied its two-panel screenshot. Across 52 epochs, training loss generally decreases while validation loss generally increases; training balanced accuracy rises toward 0.85–0.90 while validation fluctuates around 0.50–0.57 without sustained improvement. Validation peaks look brief. Exact best/final values come from the saved-summary aggregates in PROGRESS, not pixel readings. These trends support overfitting but do not identify its cause or prove ignored goals, lost spatial information, or inadequate GRU depth. The complete history was not independently inspected and baseline curves were not compared anew.

**Tran's task concern:** ADVANCE/RETRACT depends on the wire's current state, intended target and route through the vessel. Retraction can be necessary to reposition for a different bend even when the target appears ahead. Simple movement continuation or straight-line target distance is insufficient to express this concern. This is the task interpretation motivating the proposal, not a verified explanation of every dataset label; supplied labels remain operator-action proxies.

**Verified original late-goal decision path:** local `vit.py` retains one frozen DINOv2 whole-image summary of 384 values per image. `vit_gru.py` feeds six chronological `[image384, depth, time]` vectors to a one-layer, 64-unit GRU, then concatenates its final state with the separate goal384 vector for the 448→64→2 classifier. The greater output score selects RETRACT=0 or ADVANCE=1. The goal reaches the classifier but never conditions the GRU memory updates. There is no explicit tip localization, vessel connectivity or target-relative geometric representation. The dataset records `goal_xy`, but the current head does not consume it explicitly. The frozen summaries may contain useful spatial information; loss of that information is a hypothesis, not a finding.

**Why earlier goal access might help:** the current GRU produces the same summary for identical history regardless of the target. Repeating the goal alongside each step allows its learned memory updates to retain different history details for different targets. Training action-label errors provide the learning signal; the model is not explicitly taught which branch matters. Goal conditioning is valid GRU input design, but concatenation does not calculate relative position, recover absent visual details, guarantee goal use or teach route planning automatically. Training labels must supply enough relevant evidence for the extra input to help.

**Alternatives and their purposes:** more GRU layers increase processing capacity but do not explicitly add target location or route information, and the widening train/validation gap provides little reason to prioritize them. Smaller capacity/dropout/decay address overfitting, not spatial reasoning directly. Spatial patch features and correctly transformed target coordinates are more substantial representation hypotheses if whole-image summaries prove limiting; coordinates alone cannot establish the wire's route and reference/history alignment must be checked. A small targeted training-case inspection could check tip/marker/bend visibility after preparation, but Tran noted that simply re-viewing already-seen images does not itself diagnose learned features; no repeat masking or generic inspection loop is prescribed. Matched static and separately trained no-goal controls can test predictive contributions, but no-goal is a diagnostic, not the intended goal-directed model. Shuffled-goal sensitivity does not prove correctness, and original action labels cannot be assumed valid for altered targets.

**Evaluation and next decision:** compare validation BA, both class recalls/confusion counts, loss and learning trajectories on the same episode-separated partitions. Small gains on 80 cases and one seed are tentative; changed parameter shapes also prevent assuming identical initialization from the same seed. Test remains reserved. Better action-label prediction alone cannot establish correct route selection or optimal actions; stronger claims need trustworthy spatial/outcome evidence. The completed run gives a small selected-score gain with continued overfitting; prioritize discussing the matched static comparison before further architectural changes, and obtain separate authorization for any new experiment. Keep 64 hidden units for this comparison: changing memory size simultaneously would confound interpretation further, and larger input width does not require larger hidden width. Hypothesis-driven iteration—identify a limitation, change one design aspect and inspect held-out results—is normal experimental practice; a negative result is informative and should not trigger an automatic sweep.



## Representation review and three adaptation options — 2026-11-04

The discussion below records the alternatives considered before Tran selected the implemented grid iteration above; its pending-design wording is historical, not the current implementation status.

**Request/current evidence:** Tran supplied the static learning-curve screenshot, asked whether the frozen features are useful and visual history helps, and requested detailed explanations and a record of small heads, spatial patch features and last-block adaptation. The static curve shows a widening training/validation loss gap and fluctuating validation BA without sustained improvement. This establishes overfitting of the fitted pipeline, not that the encoder is useless. Static BA 61.13% and early-goal GRU 60.87% are effectively close development scores on 80 cases; differing capacity, fitting and metadata history prevent isolating visual history. No robust benefit from visual-history processing has been demonstrated. Both retain numerical movement history.

**What changes in each option:**

1. **Small regularized head, frozen image summaries.** Current static inputs are latest384 + goal384 + metadata12 = 780 values; the 780→64→2 head has 50,114 trainable parameters. A linear head learns one weighted combination rather than a hidden nonlinear layer. Sabrina already implemented this approach with train-only feature standardization, balanced class weights and L2 regularization (C=0.01/0.1/1 selected using validation BA). Her DINOv2 latest+goal+metadata probe obtained train BA 1.000 / validation BA .570; repeating that unchanged is not a new diagnostic. First inspect existing per-C results and uncertainty; a bounded stronger-regularization comparison is a possible follow-up, not guaranteed improvement. L2 penalizes classifier coefficient magnitudes, not frozen ViT weights. Feature scaling and class weighting are separate operations. Freezing prevents updates; regularization constrains parameters that do update.
2. **Frozen patch/spatial features — next representation candidate requested for exploration.** Prepared images are 518×518; Small/14 embeds a 37×37 grid of 14×14-pixel patches (1,369 patch vectors of width 384) plus the image-summary token. Later patch vectors retain a grid association while incorporating context from other patches. Current `vit.py` computes tokens but returns only the image summary. Proposed first scope: latest+goal+the same metadata, same frozen checkpoint/preparation/split; reduce patch features to a small spatial grid or a compact spatial pooling module before classification. Do not flatten all 1,369×384 values into a large dense classifier. Keep grid locations; averaging every patch into one vector does not retain an explicit spatial grid. Exact pooling/projection/head size and fair regularization controls remain to be chosen after explanation. No claim that a patch feature identifies the wire, or that a patch in the reference matches the same anatomy in the latest image. Positional differences, padding and field-of-view changes need care. This cannot recover detail already lost during resize.
3. **Last-block fine-tuning — separate adaptation candidate.** A transformer block updates feature vectors using attention and a small neural network. Unfreeze the final existing block to let action-label errors change late-stage image features while earlier blocks remain fixed; this is not adding a block. Head and final-block parameters learn, normally with a smaller encoder learning rate. The trainable scope of final normalization must be explicit. Current `@torch.inference_mode()` extraction cannot support this unchanged: provide a differentiable path and restrict optimizer/freeze checks appropriately. Frozen final embeddings cannot be reused while their producing block changes. This trains substantially more parameters and may worsen small-data overfitting; it is not the first automatic response to weak validation. Budget, memory/checkpoint limits and preprocessing must be reviewed rather than reusing the head-only runner's limits blindly.

**Teaching and class balance:** training labels supervise ADVANCE/RETRACT, not wire-tip location or route correctness. At present only the head learns from those labels. Training counts 97 RETRACT / 170 ADVANCE give a moderate imbalance. Inverse-frequency loss weights would make a RETRACT error about 170/97=1.75 times as influential as an ADVANCE error; keep all cases and original validation membership. This tests class preference, not feature quality. Sabrina already uses balanced classifier weights; Tran's PyTorch runner currently uses unweighted cross entropy. Avoid changing weighting, representation and encoder freezing together if the question is which helped.

**Highest-information question before added complexity:** the stronger-model read-only review emphasizes whether latest-image features add predictive value beyond goal+movement metadata. Sabrina's goal-only .609 and latest+goal+metadata .570 scores raise that question but do not answer it under matched fitting. Proposed narrow control: compare goal+metadata versus latest+goal+metadata with the same simple classifier family, scaling, class weighting, regularization/selection budget and episode-separated partition; avoid treating different feature widths as perfectly capacity-matched. This tests incremental latest-image utility, not all possible visual information, since the goal is itself an image. If the current summary adds little, the next representation intervention is compact frozen patch/spatial features, not an automatic larger GRU. This pair of questions is preferable to a broad architecture sweep. No run is initiated by this recommendation.
